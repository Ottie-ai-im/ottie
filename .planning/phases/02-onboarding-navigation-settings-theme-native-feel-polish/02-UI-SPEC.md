No new colors, no new font sizes, no new spacing units. New decisions are interaction patterns, copy, and component composition only.

## Spacing Scale

Source of truth: `packages/app/src/styles/tokens/primitives.ts` `spacing` object. **Do not add values.** Every spacing decision in this phase MUST come from this scale.

| Token          | Value | Usage                                                                               |
| -------------- | ----- | ----------------------------------------------------------------------------------- |
| `spacing[1]`   | 4px   | Icon gap inside chip, badge inner padding, tight inline padding                     |
| `spacing[1.5]` | 6px   | Icon gap inside button, dot-and-label spacing                                       |
| `spacing[2]`   | 8px   | Compact element spacing, list-row internal padding                                  |
| `spacing[3]`   | 12px  | Default vertical padding inside chat row, settings row, callout body                |
| `spacing[4]`   | 16px  | Default horizontal padding for screen content; default gap between top-level fields |
| `spacing[6]`   | 24px  | Section gap inside settings; vertical padding around welcome copy block             |
| `spacing[8]`   | 32px  | Major layout gap; padding around primary onboarding illustration                    |
| `spacing[12]`  | 48px  | Page-level vertical breaks (hero → CTA stack)                                       |
| `spacing[16]`  | 64px  | Splash logo top inset (already in use)                                              |

**Exceptions / phase-local minimums:**

- **Touch targets** — every tappable row, tab, action button, kebab trigger, chat-row swipe action MUST be ≥44px tall on native (Apple HIG / WCAG 2.5.5 AA). Use `paddingVertical: theme.spacing[3]` (12+12=24) plus icon/text intrinsic height to clear 44px; bump to `spacing[4]` if not. **No raw 44 literal in code** — let intrinsic + padding reach the threshold.
- **Hover hit-slop on web** — `hitSlop={8}` (matches existing `<CalloutCard>` dismiss button). No raw value beyond 8.
- **Swipe-left commit threshold** — `120px` (planner discretion per CONTEXT, but recommend 120px = 0.4× of a 320px-wide phone screen so the destructive zone is always visible during the gesture). Heavy-haptic warning fires at `90px` (75% of threshold). Planner may tune ±20px.
- **Math-curve loader minimum size** — 64×64 (= `spacing[16]`) for top-level loads. Smaller is forbidden (D-13 — never as a busy spinner).

**Forbidden patterns:**

- No raw pixel literals (`padding: 10`, `marginTop: 14`) in any new file. The hardcoded-color/spacing lint warning from Phase 1 already covers colors; the planner adds a spacing-literal lint rule (warn-level) as part of this phase to prevent drift.
- No fractional spacing values invented at the call site (`spacing[3] + 2`). Add a token if a new step is genuinely needed; punt to planner.

## Typography

Source of truth: `packages/app/src/styles/tokens/typography.ts`. **Do not introduce new sizes or weights.** Phase 02 declares which existing tokens map to which role.

**The contract uses exactly 4 sizes and exactly 2 weights.** Phase 1's token tree exposes 8 sizes and 4 weights for future flexibility; Phase 02 binds only the subset listed below. Any role outside this table is forbidden until a future phase explicitly extends the contract.

| Role              | Size                         | Weight                  | Line Height | Usage                                                                                                                                                                                                                 |
| ----------------- | ---------------------------- | ----------------------- | ----------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Caption / xs      | `theme.fontSize.xs` (12px)   | `weight.semibold` (600) | 1.2 (≈14px) | Number badges (unread count, pinned badge counter), Labs status pills (Experimental / Beta / Stable), timestamp meta                                                                                                  |
| Label             | `theme.fontSize.sm` (14px)   | `weight.normal` (400)   | 1.4 (≈20px) | Tab bar label (inactive), settings row helper text, chat row preview second line, settings group header sub-text                                                                                                      |
| Body              | `theme.fontSize.base` (16px) | `weight.normal` (400)   | 1.5 (24px)  | Chat row title, settings row label, welcome paragraph, error description, modal body copy                                                                                                                             |
| Heading / Display | `theme.fontSize.xl` (20px)   | `weight.semibold` (600) | 1.3 (26px)  | Settings sub-page title, modal title, callout-card title — **and** Welcome H1 + splash brand line + first-time-empty hero (rendered with rounded family + `letterSpacing: -0.4` — see "Phase-local typography rules") |

**Two-weight ceiling:** the entire phase ships using only `weight.normal` (400) and `weight.semibold` (600). `weight.medium` (500) and `weight.bold` exist in the token tree but are **not** part of the Phase 02 contract.

**Phase-local typography rules:**

- **Heading and Display share one role.** Both render at `theme.fontSize.xl` (20px) `weight.semibold` (600). The differentiator is **family + letter-spacing**, not size or weight:
  - Standard headings (settings sub-page title, modal title, callout-card title) use `theme.fontFamily.system` with default letter-spacing.
  - Display surfaces (Welcome screen H1, splash brand line, first-time-empty hero) use `theme.fontFamily.rounded` (SF Pro Rounded) with `letterSpacing: -0.4`.
  - This collapse keeps the brand voice (rounded + tightened) for the two existing prominent surfaces while honoring the 4-size ceiling. The previously-declared 22px size is **not** in the Phase 02 contract.
- **Emphasized labels (active state)** — when a Label needs to communicate "selected / active" (tab bar active state, settings group header at the top of a group, chat-row title when row is unread-emphasized), promote weight from 400 → 600 **without** changing size. The sm (14px) and base (16px) sizes are the ceiling; bumping size to indicate emphasis is forbidden in this phase.
  - Tab bar active label: `theme.fontSize.sm` `weight.semibold` (600), accent color via `theme.accent.base`.
  - Tab bar inactive label: `theme.fontSize.sm` `weight.normal` (400), `theme.text.muted`.
  - Settings group header: `theme.fontSize.sm` `weight.semibold` (600), `theme.text.primary`.
  - Chat-row title: `theme.fontSize.base` `weight.normal` (400) by default; planner may render at `weight.semibold` (600) when row is unread without size change.
- **Number badges** (unread count, Labs counter) — `theme.fontSize.xs` (12px), `weight.semibold` (600), tabular-nums when supported (`fontVariant: ["tabular-nums"]`). Single-digit and double-digit counts must be the same width.
- **Mono is reserved** — `theme.fontFamily.mono` (JetBrains Mono / Ark Pixel) only inside agent stream output, terminal, code blocks, and `$OTTIE_HOME/...` path mentions in error copy. Never in chat row labels, settings labels, or onboarding copy. Mono inherits whatever Body / Label size it sits inside (no separate mono size).
- **Rounded is reserved** — `theme.fontFamily.rounded` (SF Pro Rounded) only for the Welcome screen H1 + splash brand line + first-time-empty hero (i.e. the Display variant of Heading). No other surface.
- **Smoothed-text is reserved** (D-19) — `use-smoothed-text` runs **only** on AI streaming message bubble content. Tool-call output, completed messages, system messages, code blocks, and any non-streaming UI text render plainly. Existing scattered usages refactor to a single call site.

**Forbidden:**

- No `weight.medium` (500) on any new surface in this phase. If a designer feels a 500 is needed, the answer is: pick 400 or 600. The middle weight is reserved for a future phase.
- No `theme.fontSize["2xl"]` (22px), `["3xl"]` (26px), `["4xl"]` (34px), or `lg` (18px) usage in this phase. The four sizes above are the entire vocabulary.
- No raw `fontSize: 13` / `fontWeight: 500` literals at any call site.

## Color

Source of truth: `tokens/semantic.{light,dark}.ts`. **Phase 02 changes zero color values.** The 60/30/10 split below describes how the _existing_ semantic tokens map to surface roles in the WeChat-style nav model.

| Role             | Token (light → dark)                                                                                                                                          | Usage                                                                                                                                                                                                                                                        |
| ---------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| Dominant (≈60%)  | `theme.surface.background` (`#ffffff` → `#1A1C1B`) and `theme.surface.chat` (`#f7f7f8` → `#1A1C1B`)                                                           | Main app frame, chat list scrollable area, settings list area, message scroll surface. The chat-list pane is "the dominant surface" — every other element exists as scaffolding around it.                                                                   |
| Secondary (≈30%) | `theme.surface.sidebar` (`#f4f4f5` → `#141615`), `theme.surface.elevated` (`#f4f4f5` → `#272A29`), `theme.surface.glass.tint` (translucent)                   | Sidebar / left rail, mobile tab bar background, every modal/sheet/popover/bottom-sheet/dropdown via `<GlassSurface>` (D-16), settings group "card" containers, top-right `+` menu, chat-row context menu (long-press / right-click), command-center palette. |
| Accent (≈10%)    | `theme.accent.base` (`#1FA855` brand messenger green) and `theme.status.online` / `theme.status.connecting` / `theme.status.offline` for the daemon-dot triad | Reserved-for list below. Never used as a generic "primary action" color outside the explicit list.                                                                                                                                                           |
| Destructive      | `theme.status.destructive` (light `#dc2626` / dark `#ef4444`)                                                                                                 | Reserved-for list below.                                                                                                                                                                                                                                     |

### Accent (`theme.accent.base` `#1FA855`) is reserved for ONLY:

1. **Unread badge** on chat row (numeric red badge — wait, see below; accent green is _not_ the unread color — see "Status colors" below).
2. **Primary CTA fill** on Welcome screen "Get started" button (background-fill).
3. **Active-tab indicator** on `<MobileTabBar>` (icon + label color when tab is active; label promoted to `weight.semibold` per Typography rules).
4. **Active-row marker** on settings row when its sub-page is open on a wide layout (left 2px bar, accent.base).
5. **Pinned-row left accent strip** on chat row (2px wide accent-tinted vertical strip flush to leading edge).
6. **Toast success variant** background tint via `theme.surface.bubble.self` (already accent-tinted) when a `burnt` toast confirms `首条 agent 创建成功 / 标记已读 / 静音生效`.
7. **`<MathCurveLoader>` stroke color** (already token-driven; no change).
8. **`daemon-connection-dot` "online" state** via `theme.status.online` (palette green-400, slightly brighter than accent.base — already shipped).
9. **First-permission-approved delight toast** brand wash (one-time, localStorage-flagged).

Accent is **forbidden** on: every secondary button, every link, every regular icon, every focus ring. Default focus ring uses `theme.border.accent` (neutral); regular icons use `theme.text.primary` or `theme.text.muted`.

### Destructive (`theme.status.destructive`) is reserved for ONLY:

1. **Swipe-left "Delete" zone** background fill (chat row swipe action).
2. **Long-press / right-click context menu "Delete" / "Archive" rows** — text color only, not row background.
3. **Confirmation modal "Delete forever" CTA** — full-fill, accent-foreground text.
4. **Inline error vocabulary in callout cards** — left 2px destructive bar + status icon. Body copy stays `theme.text.primary`.
5. **Pair-scan failure pre-recovery state** (callout-card error variant — already shipped via `<CalloutCard variant="error">`).

### Status (`theme.status.online` / `connecting` / `offline`) is reserved for ONLY:

1. **`daemon-connection-dot`** indicator (already shipped, no change).
2. **Chat-row status dot** — same triad on the leading edge of an agent's chat row showing daemon health for that agent's host.
3. **Agent-status-dot** (`packages/app/src/components/agent-status-dot.tsx`) — already shipped, no change.

### Status — Labs badges (D-10):

- **Experimental** — `theme.status.statusWarning` (light `#d97706` / dark `#f59e0b`) — author-set in code.
- **Beta** — `theme.status.statusWarning` outline only (no background fill) — author-set.
- **Stable** — `theme.status.success` (= `accent.base`) — author-set.

Note: CONTEXT D-10 says "Experimental 橙 / Beta 黄 / Stable 绿". The token tree only has one warning amber token (`statusWarning`). Differentiate Experimental vs Beta by **fill vs outline**, not by color, to avoid introducing a new yellow token. Planner may revisit if visual ambiguity is reported during UAT.

### Light / dark contrast audit (THM-02 acceptance):

Every `<GlassSurface>` migration target in this phase MUST pass AA contrast (4.5:1 for body text, 3:1 for large text 18px+/600) against the resolved blur-tint background, in both light and dark modes. The audit is mechanical — it consumes `tokens/semantic.{light,dark}.ts` and the `expo-blur` tint values; it is owned by the planner as part of THM-02 acceptance, not by this UI-SPEC.

## Interaction Contract — Haptics (D-18)

Single source of truth: `useHaptic()` hook at `packages/app/src/hooks/use-haptic.ts`. Three semantic levels mapped to `expo-haptics`.

| Level    | `expo-haptics` API                 | Triggers                                                                                                                                                                                  |
| -------- | ---------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `light`  | `ImpactFeedbackStyle.Light`        | Swipe-left reaches 75% threshold; agent run-start; agent run-stop; send-message ack; cmdk result confirm; pull-up older-sessions commit; tab switch on long-press → command-center mount. |
| `medium` | `ImpactFeedbackStyle.Medium`       | Long-press menu opens; default destructive action confirmed (delete after modal confirm); welcome-screen "Get started" tap.                                                               |
| `heavy`  | `NotificationFeedbackType.Warning` | Swipe-left passes the delete commit threshold (before commit); permission-prompt arrival from daemon.                                                                                     |

**Forbidden:** Plain tap on chat row / tab / list item / settings row — **no haptic**. Tap is the cheapest interaction; haptic on tap fatigues the wrist.

**Hook contract:**

```ts
// Minimal contract — full implementation owned by planner
interface UseHapticInput {
  enabled: boolean; // from settings — user toggle
  isLowPowerMode: boolean; // from system — auto-disable
}
type HapticEvent = "light" | "medium" | "heavy";
function useHaptic(input: UseHapticInput): {
  fire(event: HapticEvent): void; // debounced 200ms per event-type
};
```
